# Axonkey UI

Axonkey 是本地设备映射工具，使用 React、TypeScript、Tauri 和普通 CSS。设计目标是清晰、紧凑、可操作的桌面控制台。用户在当前任务中给出的设计要求优先于这些默认约定。

## 从现有实现定位

路径均相对仓库根目录。按当前任务选择入口，无需通读全部文件：

| 改动 | 入口与职责 |
| --- | --- |
| 页面与顶层导航 | `src/components/AppHeader.tsx`、`src/app/AppController.tsx`、`src/appTypes.ts` |
| 布局与视觉 | `src/styles.css`；搜索 `.app-shell`、`.main-content` 及目标页面类名 |
| 设置分类与控件 | `src/components/SettingsPage.tsx`、`AutostartControl.tsx`；搜索 `.settings-layout`、`.settings-form-row` |
| 问号说明浮层 | `src/components/SettingsHelp.tsx`；搜索 `.settings-help`、`.settings-help-popover` |
| 映射页设备状态行 | `src/components/DeviceRail.tsx`，状态与跳转由 `AppController` 提供 |
| 保存与应用设置 | `src/appConfig.tsx` 的 `getStoredSettings`，以及 `AppController` 的保存、原生同步 effect |
| 原生输入设置 | `src-tauri/src/input_service/mod.rs` 的 `NativeSettings`，再定位对应平台或共享输入处理 |

先检查当前源码和相邻控件，再决定复用或扩展；下文尺寸是现有基准，不是新增一套样式系统的理由。

## 页面结构与滚动

- 顶部 `AppHeader` 与下方 `main.main-content` 是 `.app-shell` 的兄弟节点。导航独占高度，不放入页面滚动容器；页面滚动条只能从导航下方开始。
- 外壳占满视口，内容区通过 flex/grid 分配剩余空间。可收缩的内容容器设置 `min-height: 0`、`min-width: 0`，明确由哪一层负责滚动。不要让 body 和页面同时出现纵向滚动条。
- 新的全页工作区默认撑满可用高度，内容少时也保留完整页面区域。用父容器分配高度，避免重复扣减导航高度；不要给每个子区块都设置 `100vh`。
- 页面内容超出后仍须可达，不用 `overflow: hidden` 掩盖被截断的内容。映射页已有内部滚动区，可沿用；新增嵌套滚动仅用于确实独立的面板。
- 顶部禁用提示位于内容区，sticky 偏移相对内容区顶部计算。保留它占据的空间与滚动定位避让。
- 切换主页面按现有方式回到顶部；分类切换不应丢失已编辑的配置。弹窗打开时检查新的滚动容器是否仍会在背景滚动。

## macOS 毛玻璃与视觉层次

- macOS 使用 Tauri 原生 Vibrancy，当前为浅色 Sidebar 材质；配置入口是 `src-tauri/tauri.macos.conf.json`。`AppController` 只在原生 macOS 环境给根元素添加 `.macos-vibrancy`，相关样式在 `src/styles.css`；不要让 Windows 或普通浏览器跟随透明化。CSS 模糊不能代替原生窗口对桌面背景的模糊。
- 整体亮度以用户确认的 `.macos-vibrancy .app-shell { background: rgb(255 255 255 / 38%); }` 为基准：在原生毛玻璃上统一叠一层白色，减轻深色桌面透入造成的灰暗、压迫感。`html`、`body`、`#root` 和内容区保持透明，后续页面继承此亮度；不要把 `.app-shell` 又改成全透明，也不要为每页重复添加提亮层。
- 每个主面板只承担一层半透明底色，内部内容尽量透明，避免白底、蓝灰底和多层透明色叠加造成割裂。沿用现有圆角、细边框和透明度；调整局部材质时兼顾整体亮度与文字可读性。
- 红黄绿按钮所在的原生标题栏使用 `titleBarStyle: Overlay`，让 Vibrancy 覆盖到顶部。不要改为 `Transparent`：它只移除标题栏底色，会直接透出未经模糊的桌面。保留原生按钮和标题，并沿用 `.native-titlebar` 的 28px 预留区、`data-tauri-drag-region` 和主窗口拖拽权限；标题栏高度计入 `--sticky-header-height`，避免遮挡导航或挤压滚动区域。
- 映射页和设置页的左右栏是连续工作区，可用细竖线区分导航与内容。主页主状态区与运行检查各自保持连续面板，右栏只做轻微底色差异；总览保持干净背景，不恢复点阵装饰；关于页的介绍、功能卡片和更新区域使用一致的材质层次。
- 浅色选中块配蓝色标题、图标和深蓝灰说明。由深底改浅底时，同时检查副标题、快捷键摘要、状态点和勾选图标；例如“单击”下的“右 Control”不能保留深蓝底上的浅色文字。辅助文字和帮助图标不能因透明化而难以辨认，错误、警告、按下与禁用状态仍须可区分。
- 映射页顶部按键列表使用半透明卡片、柔和边框和低饱和数字徽标；普通按键不要全部使用醒目的蓝色圆点。选中键用蓝色强调，实际按下用绿色反馈，名称与配置数量保持可读。
- 输入框、操作卡片、按钮保留足够底色支撑阅读与操作，弹窗和帮助浮层优先保证清晰度，不要求所有元素透明。

## 分隔线

- **不要增加无意义的横线。** 优先用间距、对齐和轻微底色差异组织内容；只有确实需要表达独立区域边界时才使用分隔线，不为“层次感”给标题、工具栏、表单行或每个区块机械加线。
- 总览页顶部单击／双击／长按切换区下方保持无线条；macOS 映射页“当前序列”上方的触发选择区底线和序列下方的底线均已移除，后续视觉优化不得重新加回。
- 面板外边框、输入框和序列卡片边框、必要的左右栏竖向分隔与横线不同；按其实际作用保留，不因去横线而一并清除。

## 设置页：紧凑的桌面偏好表单

- 左侧分类导航、右侧当前分类内容，默认撑满可用高度，两栏等高。当前分类为启动设置、系统权限、遥控器映射、鼠标映射；同类新增项进入相应分类，不重新堆成长页。
- 设置页内部不再放“设置”总标题或整行工具栏，直接从左右两栏开始。右侧保留当前分类标题；“更改自动保存”等公共提示放在分类级。
- 表单采用“右对齐标签 + 左对齐控件”的两列布局，标签末尾使用中文冒号。控件紧邻标签，不推到页面最右端；同组的标签、输入起点和单位对齐。
- 普通设置行不放大图标、说明段落、独立卡片或逐行分隔线。用浅灰底色、适度组间距和原生感控件表达层次。这是设置页约定，不要求映射工作区、主页等页面全部改成表单。
- 复用 `.settings-form-fields`、`.settings-form-row`、`.settings-form-label`、`.settings-form-control`。当前基准：标签列约 150px，列间距约 12px，行高至少 32px，行间距约 18px，正文 14px；数值框约 94 × 30px，滑条含数值约 240px。尺寸随内容和窗口调整，避免强行压缩文字或让控件溢出。
- 分类状态由 `AppController` 管理，切换分类不丢失已编辑值。映射页设置入口应指定目标分类，不能只跳到设置页默认分类。

## 控件与说明

- 沿用现有字体、浅灰背景、细边框、蓝色选中态和 `lucide-react` 图标。新样式限定到页面或组件，优先更新现有规则，避免累积冲突覆盖。
- 设置表单的布尔选项使用带文字标签的复选框；顶部全局开关和设备状态行仍使用开关，不因表单风格而替换。
- 连续参数使用滑条并实时显示当前值；精确时长使用数值框，数值右对齐、单位紧邻。范围、默认值和特殊值含义放进该字段的帮助说明，例如“默认 0 毫秒，不限制触发间隔”。
- 标签与输入关联，复选框和开关有可访问名称；保留键盘操作及 focus-visible。分类导航标记当前项，隐藏分类不进入焦点顺序。
- 介绍文案统一使用 `SettingsHelp`：控件旁放圆圈问号 `CircleHelp`，不用感叹号或常驻说明段落。悬停、键盘聚焦或点击均可展开；点击不固定展开，光标离开问号与浮层区域后关闭。保留跨越两者间隙的短暂关闭延时，进入浮层取消关闭；失焦、Esc、外部点击、滚动和窗口变化时关闭。
- 浮层通过 portal 放到 `document.body`，按触发按钮定位并避开视口边缘，不撑高表单或被滚动容器裁切。复用已有组件，不为新字段实现独立 tooltip。
- 错误、未授权、需要重启等影响操作的状态直接显示，不藏进问号；帮助文字说明用户可感知的结果及必要限制，使用简体中文。

## 系统权限与设备状态

- macOS 权限页不显示“系统权限已就绪”汇总卡片。每行左侧为权限名称，右侧紧邻授权状态、操作按钮、问号说明；不要让按钮远离状态。
- “重新检测”属于系统权限分类，在该分类标题旁使用小圆形刷新图标按钮，带可访问名称和悬停提示。检测中或环境不支持时禁用；不放到设置页右上角全局区域。
- 保留逐项真实权限状态、授权动作和异常提示；浏览器预览不能显示成已授权，平台差异按实际能力表达。
- 映射页鼠标状态行顺序为“授权状态 / 功能开关 / 设置齿轮”。齿轮直接进入设置页鼠标映射分类，权限状态与功能开关各自表达独立含义。

## 新设置项的完整接入

新增设置时同时确认：类型、缺省值、旧配置兼容、读取与范围约束、控件状态、本地保存，以及实际功能所需的原生同步。默认值不应意外改变旧用户行为；不要出现“界面可调，执行端忽略”的设置。

- 普通配置沿用自动保存、即时应用和现有保存失败反馈；系统权限、驱动安装等操作保留明确动作入口。
- 控件的范围与执行端的有效范围一致；数值含义跨平台一致。无法支持的平台应明确解释或按现有约定不显示。
- 只调整布局时不改设置含义、默认值或输入处理逻辑。

## 完成与验证

- 纯样式小改动检查 diff，做与变化相称的构建或页面验证；不要为 CSS 数值、文案复制式地新增测试。TSX 或类型变化运行 `npm run build`。
- 对高度、滚动和分类导航改动，在实际受支持的窗口尺寸中检查短内容、长内容和较矮窗口。验证导航固定、内容可滚动、末项可达、控件无横向溢出，以及切换后的焦点和状态。
- 验证滚动时实际滚动一个超出容器高度的页面；不能用无溢出的页面证明滚动正常。桌面最小宽度以当前 CSS 和 Tauri 配置为准，不把被 `min-width` 撑开的页面当成小屏适配成功。
- 页面视觉改动优先看浏览器或桌面实际效果；截图不可用时可测量 DOM 布局，但不要把尺寸检查称为视觉验收。浏览器预览不能证明原生 Vibrancy 的桌面透色、Tauri 权限、保存到原生服务或硬件输入已生效。
- 问号交互改动检查悬停、点击后离开、进入浮层、键盘聚焦与关闭；不要只验证首次展开。
- 涉及新行为或共享设置契约时补充对应行为测试。输入服务变更可运行 `cargo test --manifest-path src-tauri/Cargo.toml --lib input_service`；测试关键默认值、边界与实际行为，不重复扫描代码文字。
- 收尾说明具体变化、已做验证，以及仍未验证的运行环境。不要因编写页面而自行发布、升级依赖或重构无关页面。

## README 界面截图

仅更新 README 截图时，按本节处理，无需执行桌面 UI 的构建或交互验证。

- 首页、总览、映射截图分别使用 `docs/images/axonkey-home.png`、`docs/images/axonkey-overview.png`、`docs/images/axonkey-mapping.png`；替换对应文件，保留 README 的相对路径与显示宽度。
- 默认每张控制在 **300～500 KB**，保留 PNG 格式及文字可读性；原图已经小于目标时不为凑下限增大文件。
- 先移除元数据并做无损压缩；仍超过 500 KB 时，从原始截图等比缩小，避免反复缩放已压缩版本。宽度 1500px 可作为尝试值，最终以体积和清晰度决定，不裁剪界面内容。
- 可用 ImageMagick：`rtk proxy magick "$source_image" -strip -define png:compression-level=9 "$output_image"`；需要缩小时，在 `-strip` 前加入 `-resize '1500x>'`。
- 完成后检查每张文件大小、图片能否打开、缩放后的文字清晰度及 README 引用；汇报最终体积。纯截图替换无需运行应用构建。
