# 设备扫描、实例绑定、映射工作区与后台输入接入

本约定面向后续遥控器、手柄、旋钮和自定义固件设备。设备首页是统一入口；每个实物设备拥有独立身份、配置和运行状态。编辑页面选中哪个设备，不决定后台监听哪个设备。

## 用户流程

1. 安装并启动 Axonkey，首页自动展示内置支持包能够识别的在线设备和系统已配对设备。已配对的设备休眠、关机或断开后仍显示，状态为“未连接”；在系统中取消配对后移出发现列表。扫描不代替系统蓝牙配对。
2. 点击扫描到的设备，进入集成流程，确认实例名称、目标实物及平台准备状态。
3. 完成需要的驱动安装或系统授权后，绑定并启用实例；后台自动开始监听。权限缺失、打开失败、需要重启等状态必须真实显示，不能把“保存配置”当作“集成已就绪”。
4. 右上角“手动添加设备”允许选择内置支持包、离线建立实例和编辑配置。未扫描到实物时保持“等待绑定”，出现后由用户明确选择并绑定。
5. 同型号可以添加多个实例，例如客厅遥控器、书房遥控器；不限制一个型号只有一张卡片。一个物理设备同时只能归属一个实例。

用户不需要扫码。手动添加是自动发现的补充入口，并非另一套配置系统。

## 必须分开的概念

| 概念 | 职责 | 不能替代它的值 |
| --- | --- | --- |
| 支持包 / 设备类型 | 匹配规则、协议解码、能力、图形资源、平台准备步骤 | 不能表示一只具体设备 |
| 发现结果 | 在线 HID 与系统配对记录合并后的设备列表，分别记录 connected、paired 与身份可靠性 | 已配对不能表示当前在线、已集成或已授权 |
| 设备实例 | 用户保存的独立设备记录，有实例 ID 和名称 | 不能以型号或 VID/PID 作为实例 ID |
| 实物绑定 | 某个实例与明确物理身份的对应关系 | 不能自动选择第一个同型号设备 |
| 集成状态 | 连接、驱动、权限、绑定、运行模式及错误 | 不能只用 connected 一个布尔值 |
| 输入能力 | 按键、轴、扳机、旋钮等及范围、可用触发方式 | 不能永远固化为一张按钮列表 |
| 配置文件 | 某实例的映射与当前激活配置 | 不能按型号共享 activeProfileId |
| 后台会话 | 打开句柄、协议状态、手势状态、动作队列、取消信号 | 不能由页面组件拥有 |

系统鼠标仍是现有的系统级输入源，当前不按物理鼠标区分。RC003 语音由
`AudioServiceManager` 按实例维护，实例配置保存自己的输出设备和增益；旧设置页和
Windows A15 录音保留兼容服务。Windows GATT 会话按绑定蓝牙地址筛选，macOS 的
CoreBluetooth 设备身份仍需实机验证多只同型号同时连接时的绑定准确性。

## 身份与同型号多实例

- 优先使用经过适配验证的序列号等稳定身份。当前 HID 支持包结合类型、VID/PID 和序列号计算本地指纹，不把原始序列号显示或写入日志。
- 蓝牙地址形式的序列号统一格式后计算指纹，并兼容已有绑定的地址格式。在线 HID 与配对记录通过这个指纹合并，不能用同名或同型号猜测为同一实物。
- macOS 上序列号不是地址的设备（例如 RC003），通过对应 IORegistry 设备节点的 `DeviceAddress` 关联。已有实例首次在线时补充服务端维护的 `bindingPairingId`，不改变实例 ID、原绑定 ID 或映射；以后离线启动也可与配对记录合并。该字段可缺省，兼容旧版实例文件。
- VID/PID、产品名和“第几个设备”只能识别型号或扫描顺序，不能唯一绑定实物。
- 没有可靠序列号时，只授予本次连接的临时身份。断开或重启后必须重新绑定；不靠接口路径猜测是否为原设备。
- 多个设备报告相同稳定标识时，视为冲突，不打开其中任意一个。UI 提示用户消除歧义。
- 未来支持复合 HID 设备时，支持包须明确物理设备与多个接口/collection 的聚合规则。不能把同一设备的每个接口都当成独立实物。
- 实例可改名、暂停、解除绑定但保留配置，或移除。重新绑定只允许匹配该实例支持包的设备。

例如两个 RC003 可以使用同样的 `power` 输入 ID，因为运行时寻址是 `(instanceId, inputId)`。两只设备的单击不能合成一次双击，切换其中一只的配置不能改变另一只。

## 平台准备与设备拦截

### Windows

驱动是支持包的能力要求，不是所有设备的统一前置步骤。标准 HID 手柄使用系统 HID；不能为手柄强行安装 RC003 键盘驱动。需要专用驱动的设备进入现有安装流程，保留管理员授权、安装失败、驱动版本和需要重启等真实结果。

当前新实例层的 Windows 手柄独占拦截尚未接入，绑定后显示暂不支持，不启动共享监听。RC003 的 Windows 按实例驱动适配尚未接入，继续使用原工作区及 Quarbor 驱动；新实例页面会直接说明限制，不能把安装驱动等同于获得按实例拦截能力。

### macOS

使用系统 HID 服务；系统授权在集成检查中可见，并可进入现有权限页处理。输入监控与辅助功能分别检查：读到报告并不意味着有权注入键盘或鼠标事件。权限不可由浏览器预览伪造。

RC003 的电量沿用已有原生读取：首页发现卡片、已集成卡片和内部编辑页复用 `BatteryIndicator`，保留低电量、满电和未知状态。当前电量接口没有物理设备标识，仅在唯一一只 RC003 在线且身份明确时关联到它；离线实例或多只同型号同时在线时显示未知，不能把同一个数值复制给所有实例。未来扩展电量读取须随报告携带物理设备身份。

### 绑定后独占拦截

- 设备绑定并启用后默认独占，不提供输入模式选择或共享监听。
- macOS 标准手柄使用 HID 独占打开，成功后才报告独占状态；整个设备的原始输入被拦截，包括未配置按键。停用后释放句柄。
- RC003 沿用专用拦截实现。macOS 实例复用原输入服务、硬件修饰键映射、事件过滤与电源键保护；未配置按键透传保持原行为。停用后释放输入并恢复硬件映射。
- 当前 Windows 手柄和 RC003 按实例拦截尚未接入，显示真实的不支持状态；RC003 可继续使用原驱动工作区。

## 生命周期

后台服务由 Tauri 应用启动，每两秒扫描在线 HID，独立线程每五秒读取系统配对记录，慢查询不会阻塞输入读取。编辑页只查询状态、提交配置并订阅带实例 ID 的输入事件。

- macOS 读取 `system_profiler SPBluetoothDataType -json` 的在线与未连接设备记录；Windows 使用 Bluetooth / Bluetooth LE 的已配对设备选择器和系统设备属性。只接受支持包匹配的 VID/PID，不凭设备名称猜测协议。
- 配对记录中的连接标志不能代替实际可用的 HID 句柄；只有在线 HID 才会启动监听。已配对但离线的稳定身份可以先绑定，重连后自动开始监听。
- 系统配对查询失败时保留上次成功结果并显示错误，不把查询失败当成全部取消配对。
- 已保存的设备实例及配置独立于发现列表；断连、扫描为空和系统取消配对均不删除配置。取消配对只移除未集成的发现卡片，已集成的卡片继续显示“未连接”，由用户显式移除实例。

```text
手动添加 → 等待绑定 ─┐
扫描发现 → 选择实物 ─┴→ 绑定 + 启用 → 打开设备 → 独占拦截
                                 ↘ 失败 → 显示错误并重试
运行中 → 停用 / 总开关关闭 → 释放句柄、取消手势和待执行动作
运行中 → 断开 → 释放状态 → 稳定身份等待重连 / 临时身份要求重绑
运行中 → 配置切换或修改 → 取消旧动作与手势，应用该实例的新配置
移除 / 退出应用 → 停止监听、清理队列与句柄
```

- 关闭或切换编辑页不会停止后台服务；退出应用会停止。
- 每实例独立输入状态、手势判定与配置。通用动作队列有界，溢出显示错误；macOS RC003 在各自的原输入服务内执行动作，转发的报告只更新实例 UI，通用层不得再次执行映射。
- 延迟动作定期检查取消状态；停用、解绑、移除、配置变化、断开后不继续旧序列。
- 标准手柄的通用动作输出使用完整的按下/释放序列，目前不提供按住输出键、连续鼠标移动或虚拟手柄轴。RC003 保留原实现已有的按住与连续输出；断开、停用或切换配置时，原输入服务负责释放按住状态。以后扩展输出语义时必须增加失联释放测试。
- UI 输入反馈最多约 25 Hz；原始报告持续在原生端解码，不通过 React 逐包传递。
- macOS HID 库的全局管理器绑定创建线程的 RunLoop，必须在该线程退出前关闭；生命周期实机测试覆盖了重新创建服务。

## 配置与兼容

原生设备实例保存在 Tauri `app_data_dir()/device-instances.json`，schema 版本为 1。保存采用临时文件、同步和备份替换；无法解析时保留原文件并显示错误，不静默清空。请求携带 store revision，旧页面不能覆盖已发生的配置切换。

设备实例不再保存 `capture` 字段。旧配置中的该字段读取时忽略，下一次保存时移除，保留物理绑定、配置内容和当前配置。型号专用输入实现与物理实例管理分层：实例层负责稳定身份、绑定、启停、配置和状态，设备支持包保留该型号已验证的输入语义。

```json
{
  "version": 1,
  "revision": 2,
  "instances": [
    {
      "id": "unique-instance-id",
      "kind": "xboxBluetooth",
      "name": "桌面手柄",
      "binding": "hashed-physical-identity",
      "bindingQuality": "serial",
      "enabled": true,
      "activeProfileId": "default",
      "profiles": [{ "id": "default", "name": "默认配置", "behaviors": {} }]
    }
  ]
}
```

现有型号级配置与工作区保留，遥控器实例设置可显式复制原配置。首次集成某型号时继承原有配置及当前选择，保持配置顺序；已有首个实例若仍是未编辑的“默认配置”占位，则恢复原配置。已有映射、改名或多个配置的实例不覆盖，后续同型号实例不自动继承。`legacyProfilesMigrated` 记录一次性迁移，清空配置后不会再次导入。迁移只复制配置，不推断或更换实物绑定。

macOS 一旦为 RC003 建立实物绑定，旧 RC003 服务必须关闭 IOHIDManager 及设备句柄后，新实例才能打开监听；只设置旧映射 `enabled=false` 不会释放句柄。解除所有 RC003 绑定后才交还旧服务。RC003 的原生事件监听和硬件映射均按序列号限定实物；IOHIDServiceClient 未提供 SerialNumber 时，通过该服务的 IORegistry 条目读取。

浏览器使用独立预览存储 `axonkey.device-instances.preview.v1`，没有真实发现或监听，不与原生绑定混用。现有设置页的 v2 数据备份仍只覆盖原型号级配置；新实例文件目前需单独保存，后续统一备份应加入实例配置并在恢复时要求确认绑定，不能直接抢占另一台电脑的同型号设备。

## 映射工作区布局

### 默认首选：左侧设备、中间多泳道、右侧行为库

新设备接入时，**默认优先采用泳道式拖拽编辑布局**，以现有系统鼠标工作区为参考：左侧选择设备输入部位，中间编辑动作序列，右侧提供行为库。

| 区域 | 默认内容与交互 |
| --- | --- |
| 左侧设备区 | 设备示意图及可点击的输入部位，清晰标记当前选中项、已配置项和实际输入反馈；保留必要的权限状态与设备开关 |
| 中间编辑区 | 针对当前输入，并排展示单击、双击、长按泳道；从行为库拖入动作、拖动排序、编辑动作及拖入删除区，沿用已有序列操作 |
| 右侧行为库 | 常驻展示搜索、分类、行为与预置，支持拖入目标泳道；列表可滚动，名称和拖拽目标清晰可见 |

泳道按该输入实际支持的触发方式展示；设备只有一种触发方式时只显示对应泳道。设备示意图、输入名称和泳道内容保持同步，选择输入部位后直接编辑它的映射。

### 大型或密集设备：顶部触发按钮加单泳道

**设备较大，或设备区内容多、杂、难以点击时，优先把中间编辑区收为单泳道。** 手柄是典型场景，但不按设备型号硬性区分；遥控器、旋钮或自定义设备出现同样的空间问题时也采用此布局。

- 左侧设备区加宽，给完整设备示意图、摇杆方向、肩键、扳机等输入部位留出足够的显示与点击空间；不要为了保留多泳道而把设备图和点击区域不断缩小。
- 单泳道只占中间一条紧凑的编辑区域，不随窗口无限拉宽；手柄页以约 220～280px 为基准，额外宽度优先留给设备示意图。图示按可用宽度和高度等比适配，确保完整内容可见。
- 中间仍使用可拖拽的泳道编辑器，一次只显示当前触发方式的动作序列。泳道上方放独立的“单击”“双击”“长按”切换按钮，当前项有明确选中态；仅展示该输入支持的触发方式。
- 右侧行为库继续常驻，并可加宽，让搜索、分类、行为名称和拖拽操作更舒展。减少泳道节省出的宽度优先分配给设备区和行为库，同时保留单泳道内动作卡片的可读性与拖放空间。
- 切换触发按钮只切换当前可见序列，保留其他触发方式已配置的动作；动作增删、编辑和排序作用于当前输入的当前触发方式。布局变化不改变配置结构、保存方式或执行语义。

### 布局选择与实现约定

| 判断条件 | 推荐布局 |
| --- | --- |
| 设备图紧凑，输入部位易辨认、易点击，各区宽度充足 | 默认采用多泳道，便于同时查看不同触发方式 |
| 设备图较大或横向展开，例如手柄 | 采用单泳道与顶部触发按钮，扩大设备区和行为库 |
| 输入部位多、标注拥挤、点击区域难以区分 | 采用单泳道，优先保证设备选择的清晰度和可操作性 |
| 多泳道在受支持的窗口尺寸下明显挤压设备区或行为库 | 收为单泳道；不靠整体缩小文字、图形和点击目标维持多泳道 |

布局选择以实际内容和可用宽度为依据，不强制所有设备使用相同列宽。顶部保留设备名称、当前配置和返回入口；各区的滚动与焦点遵循 [axonkey-ui](../.agents/skills/axonkey-ui/SKILL.md)，长序列和行为库末项必须可达。

实现时优先复用并扩展 `src/components/WorkflowAxonkey.tsx` 及配套泳道、行为库组件，使单泳道和多泳道共享拖拽、动作编辑、序列操作与保存逻辑。单泳道是拖拽编辑器的布局变体，不以简化的动作表单或列表代替。

RC003 实例工作区直接复用 `WorkflowAxonkey` 的单击、双击、长按三泳道，以及 `ProfileManager`、`DeviceWorkspaceHeader`。设备断线、重连或变更运行状态不切换编辑器。每次编辑以实例和配置 ID 定位，切换配置行为的覆盖确认也限定在当前实例。

手柄实例同样复用 `WorkflowAxonkey`，通过 `activeTrigger` 一次显示单击、双击或长按中的一个泳道；顶部独立按钮显示当前触发方式及动作数量，左侧扩大手柄示意图，右侧常驻行为库。切换触发方式只更新可见泳道，保留同一个编辑器、各泳道的动作与滚动位置；配置仍按实例、配置文件和输入 ID 独立保存。

## 当前手柄支持范围

- 验证对象：Xbox Wireless Controller 蓝牙 `045e:02e0`，Usage Page 1 / Usage 5。
- 16 字节 Report 1：双摇杆、LT/RT、帽开关和 10 个普通按键；Report 2 的主键单独更新，不能因此释放 Report 1 上的按键。
- A/B/X/Y、LB/RB、View/Menu、LS/RS 点击、十字键四方向、左右摇杆各四方向、LT/RT；主键依设备与系统是否上报，分享键未启用。
- 轴归一化；方向和扳机在 55% 进入、低于 35% 释放，以滞回避免抖动。单击、双击、长按使用统一手势层，双击窗口 300 ms，长按 600 ms。
- 不因外观相同就复用协议。其他 PID、USB 模式、更新固件布局需要新增匹配与协议样本。
- 编辑页仅从 SVG 选择输入，不增加手柄按键列表；图中无 Xbox 品牌图标，标准按键字母保留。

## 新设备接入清单

1. 收集真实枚举信息、身份特征、接口结构、报告描述和按下/释放/中立样本，注明连接方式和固件。
2. 定义严格匹配的支持包及能力；未知型号不能直接套用相似设备的解码器。
3. 提供设备卡片资源与交互视图，映射区域绑定稳定的输入 ID，保留键盘操作与状态反馈。按“映射工作区布局”选择默认多泳道或大型、密集设备的单泳道方案。
4. 接入原生发现和协议解码，事件必须携带实例 ID；输出复用动作执行层。
5. 声明每个平台的驱动、权限、独占和透传能力；不可支持的功能直接标注。
