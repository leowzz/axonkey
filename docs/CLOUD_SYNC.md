# 账号与云端同步

Axonkey 的本地映射、设备管理、配置编辑和保存不依赖账号或 Relay。账号入口在“设置 → 账号与同步”，没有启动登录门槛。退出登录、会话失效、断网或后端异常都不会清除本地配置或停止本地输入服务。

## 使用

1. 可选择邮箱或中国大陆手机号验证码登录；首次登录由 Relay 创建账号。点击“获取验证码”时先自动完成人机验证，失败可重试；验证期间不影响本地功能。
2. 登录不上传配置，也不开启自动同步。“同步一次”上传当前配置，完成后自动同步仍保持关闭。
3. 开启“将本机修改同步到云端”后，应用在运行期间每 5 秒检查变化，有变化才上传。失败保留本地配置，至少等待 60 秒再自动重试。关闭开关后停止后续自动上传。
4. “从云端恢复”先读取云端，再由用户确认应用到本机。恢复会关闭自动同步并重新加载界面。本机同一实例的绑定保留，新实例不绑定实物；本机独有的实例保留。恢复不是版本历史或自动合并，确认后不能撤销。多个设备分步保存，失败时提示已恢复数量，重试可继续恢复。
5. 首次同步会直接补齐空的或没有差异的云端设置。两边已有不同配置时，以普通选择提示询问使用哪份，不显示成同步失败；点击“使用本机配置并同步”即可确认上传，也可从云端恢复。其他电脑或控制台改过对应配置时仍保留版本检查，避免自动覆盖。云端没有历史版本，本机删除设备不会删除云端备份。

登录后，顶部“账号与同步”标题旁显示“前往控制台”。点击后在系统默认浏览器登录当前账号，不触发配置上传。跳转使用 60 秒有效的一次性凭据，不在网址中携带长期令牌；控制台会建立独立会话。需要 Relay 后端和控制台均部署对应临时凭据接口，详见 Relay 的 `docs/api.md`。

## 云端行为库

新版行为库默认打开“推荐”，按云端顺序展示；“社区”只展示审核通过的分享。浏览、搜索和添加不要求登录，添加后保存为本地副本。云端不可用时仍可使用“基础”、本地常用行为和“我的”序列。

在“我的”中点击分享图标，检查完整步骤后确认提交，备注可留空。分享使用当前登录账号，不要求开启自动同步；审核通过后公开。分享窗口可查看状态、撤回申请或取消公开。删除本地序列不会撤下社区分享，其他人已经采用的副本也不受撤回影响。

分享会上传所确认序列的文本、路径和网址，默认声明适用于当前操作系统。添加公开行为时只上报条目与系统的添加计数，不上传映射内容，也不统计实际按键执行次数。

## 同步范围

- 设备实例名称、启用状态、全部配置方案、当前方案、音频增益与录音方式。
- 鼠标映射、保留的旧版 RC003 / A15 型号配置、个人“已保存”行为库。
- 软件总开关、鼠标参数、界面布局偏好、录音悬浮窗和语音补偿设置。

不上传硬件绑定、驱动目标、权限状态、开机自启、调试状态、账号令牌或输入历史。配置里的文本、路径和网址属于配置内容，会随用户选择的同步上传；跨系统恢复后可能需要调整本机路径。

## 开发与服务端准备

行为库接入 `/v2/behavior-library` 的公开列表、分享与撤回接口，需要 Relay 行为库迁移 00006。客户端变更仍待打包发布；公开列表已做线上只读验证，分享写入仅做本地接口桩验收。

桌面版通过原生 HTTP 连接 `https://relay.wleo.cn/api`，浏览器开发预览通过 Vite `/api` 代理连接同一服务。预览也使用真实认证接口，不内置测试登录；浏览器预览的登录仅保持在当前页面内存中。

新版登录使用 `/auth/captcha` 获取公开配置，再自动完成 Cap HashWX 验证，向 `/auth/v2/code` 提交一次性 `captcha_token`，通过 `/auth/v2/verify` 登录。不回退旧路由，Cap 不可用时保留输入并提示重试。已发布版本继续使用原登录接口，已有会话的刷新与云端同步协议不变；本次源码变更将在后续新版本引入，不修改当前已发布安装包。

Cap 组件 0.1.58、WASM 0.0.8 和 pako 2.1.0 均从 `cap.wleo.cn/assets/` 加载；覆盖组件的两个 WASM URL 与 pako 回退 URL，不使用默认海外 CDN。应用样式不再远程加载 Google Fonts，使用现有字体回退。当前站点使用 HashWX，不启用 instrumentation。原生 WebView 仍需随新版包分别验证 macOS 与 Windows。

按项目约定，桌面版刷新令牌、账号信息和刷新重试 ID 保存在软件数据目录的 `relay-session.json`，access token 仅保留内存。会话文件不进入配置导出与云端同步。重启后只在需要云端操作时刷新会话；刷新请求串行执行，超时重试复用原 UUID。会话文件先写临时文件再替换，保存失败不会发出后续刷新请求，退出登录删除会话文件。

Relay 须具备设备文档 schema 1、软件设置 schema 1 和 `mouse` 型号目录。配套迁移位于 Relay 项目的 `migrations/00004_axonkey_system_mouse.sql`；发布前按 Relay 原有流程执行 `make migrate-up`，或者由管理员在目录中补齐 `axonkey / mouse`。缺少型号时客户端会在写入前报错，不会声称全部同步成功。本次源码变更不代表已迁移共享数据库或部署服务。

设备实例使用原本的实例 ID 作为 `instance_key`；鼠标使用 `system-mouse`，旧型号映射使用 `legacy-rc003`、`legacy-cmiotA15`。客户端云端修订记录按账号隔离，服务端 `revision` 与本地设备 Store 修订号互不替代。

验证命令：

```sh
npm run test:cloud
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --lib relay::tests
```

自动化测试覆盖启动不自动同步、匿名浏览行为库与离线兜底、分享确认与撤回、登录不上传、手动与自动同步、断网保留配置、令牌刷新重试与会话失效、修订冲突、恢复确认和可迁移字段。测试不向真实收件人发送验证码，不代表真实账号、macOS 原生环境或硬件输入的联合验收。

## 排查日志

通过首页的日志入口打开现有运行日志目录，搜索 `[relay]`（前端操作）和 `axonkey::relay`（原生文件/网络故障）。无需开启额外调试开关。

- `operation.start` / `operation.complete` / `operation.failed` 包含操作名称、结果与耗时；验证码通道、登录、退出、控制台跳转、手动/自动同步及恢复均有记录。
- `request.complete` 包含方法、API 路径、HTTP 状态、耗时和 `server_request_id`，可使用该 ID 对照 Relay 服务端日志。原生网络失败另记录超时、连接或响应解析阶段。
- `session.*` 记录本地会话加载/保存、刷新及失效。`refresh_request_id` 用于核对超时后是否复用了同一刷新请求，不是登录凭据。
- `sync.snapshot` 仅记录配置数量及是否选择覆盖；`sync.conflict`、`sync.deferred` 分别表示等待用户选择和暂缓重试。自动同步没有配置变化时不刷日志。
- `restore.preview` / `restore.confirmed` / `restore.cancelled` 区分查看、确认与取消；`auth.logout.local_only` 表示已清除本机登录，但云端撤销未完成。

日志不记录验证码、邮箱/手机号、access/refresh token、控制台临时凭据、请求/响应正文或配置内容。接口失败记录状态与错误码，不输出可能含账号或配置内容的服务端错误详情；未知本地异常只记录类型和所在阶段。日志写入失败不会阻止账号操作或本地功能。
