# 手柄空间 · 场景设计

## 定位

独立于按键映射的场景功能：用户选择要做的事，直接操作可见对象。首页设备卡进入「手柄空间」，配置场景、常用目标和唤出方式；不要求逐键填写快捷键。此目录为交互提案，未接入原生服务。

设计延续 Axonkey 的浅色桌面控制台。交互探索覆盖近距离桌面、沙发大屏和演示投屏，不改动现有应用。视觉变化 6 / 动效 4 / 密度 5 / 素材依赖 2 / 品牌忠实度 8：导航稳定，五个场景采用不同空间结构，运动仅表达选择、移动和连续参数。实际应用图标来自 `src-tauri/icons/icon.svg`；不绘制仿真的 Xbox 产品外观。内容均标明示例。

## 视觉系统

- 颜色：沿用 `src/styles.css`，文字 #202327、次级 #73777d、蓝 #1478e8、浅蓝 #e2efff、底色 #f2f3f4；影音与审片用同一中性色系的深色表面。
- 字体：沿用 Manrope / 中文系统字体的无衬线体系；数字等宽；不依赖联网字体。
- 间距：4px 基准，8 / 12 / 16 / 24 / 32px。
- 圆角：控件 8px，面板 16px，浮层 24px；仅轮盘和摇杆使用圆形。
- 阴影：普通面板不加阴影；浮层一层柔和阴影；当前窗口以蓝色轮廓突出。
- 动效：160–240ms；连续轴输入按帧更新；遵循 reduced-motion。
- 容量：主舞台约 2/3，说明与试用面板约 1/3；窄屏上下排列。

## 场景比较

| 方案 | 使用时刻与价值 | 核心空间 | 模拟量的作用 | 第一版取舍 |
| --- | --- | --- | --- | --- |
| A 快捷轮盘 | 手离开键鼠后，开应用、切场景、进入专注 | 六向轮盘，最多一层子菜单 | 左杆方向选择；中心死区不执行 | 推荐作为所有场景共同入口；选择后 A 确认 |
| B 沙发影音 | 电脑接电视，看长视频、听音乐 | 大字播放台与章节轨道 | LT 倒退 / RT 快进，深度决定速度；右杆音量 | 推荐首先接一个播放器；暂停或播放状态在松扳机后恢复 |
| C 空间桌面 | 整理多窗口、临时分屏 | 可抓取的窗口平面 | 左杆移动，右杆缩放；LT 精调，RT 吸附 | 后续做，依赖系统窗口 API；整次抓取可撤销 |
| D 演示讲解 | 站立讲课、遥看投屏、讲图表 | 全屏内容 + 光点与聚光 | 左杆移动光点；RT 聚光；LT 放大，右杆平移 | 推荐低成本验证；翻页与黑屏单独明确 |
| E 剪辑审片 | 浏览长素材、找关键帧、做标记 | 时间线 + 变速回看 | 双扳机正反穿梭；左杆连续拖动；右杆缩放时间轴 | 专业拓展；先只支持一个编辑器插件或开放 API |

这些场景适合浏览、导航、空间操作和连续调节；大量文字输入、复杂精确绘图、需要同时记忆很多指令的工作不作为主要用途。不要把普通 Xbox 控制器假定为陀螺仪设备，演示光点由摇杆移动。

## 统一交互契约

1. 用户先在 Axonkey 选择目标场景；默认 Menu 按一下唤出，再按收起。原生版需要检查应用和系统冲突，必要时换为组合键；不把 Xbox Guide 键作为唯一入口。
2. 唤出 → 选择/预览 → A 确认 → 可见结果。B 返回上一层或取消当前事务。未确认的菜单选择不能自动执行。
3. 左杆处理方向或主要对象，右杆处理辅助连续参数；十字键用于离散定位。每个场景持续显示当前语义。
4. 模拟量按真实输入归一化。原型默认摇杆死区 18%、进入门限高于退出门限，离散选择有重复延迟。可在 Tweaks 调整死区。
5. 影视与审片扳机按 `16 × pressure²` 控制穿梭倍率；两侧同时按则取差值。松开停止穿梭并恢复原播放状态。掉线、失焦立即清空连续输入并暂停演示。
6. 原生版只有显式进入场景时才接管输入；游戏运行时默认暂停接管。输入独占必须单独实测，不能把监听输入当成阻止游戏收到输入。
7. 浏览器可选读取 standard 布局 Gamepad，其他布局明确提示尚未适配；没有手柄时虚拟摇杆、扳机和键盘均可操作。本原型只改页面里的示例。
8. 设备断连后取消抓取、停止穿梭、撤销未提交预览；重新连接需重新进入，不能突然恢复旧的连续动作。

## 落地结构

建议单独实现 `ControllerSpace` 场景运行时：设备输入归一化 → 场景状态机 → 场景渲染 → 语义命令执行器。独立的 sceneProfiles 记录常用场景、目标应用和参数，不复用单击/双击/长按行为编辑器。每个物理实例保存独立配置。

底层可以使用应用 API、插件或受控的快捷键适配器执行语义命令，但产品层始终是「播放 / 章节 / 放置窗口」这样的对象操作。应用未支持时显示不可用及原因，不伪装成通用支持。

第一阶段推荐 A + B：建立唤出、选择、取消和连续输入的共用机制，并只集成一个播放器。D 可作为第二个验证场景；C 与 E 等窗口 API、编辑器接口选定后再做。

## 能力依据（2026-10-25 查阅）

- [Microsoft XINPUT_GAMEPAD](https://learn.microsoft.com/en-us/windows/win32/api/xinput/ns-xinput-xinput_gamepad)：双摇杆四个有符号轴，LT/RT 各自独立的 0–255 模拟值；公开按钮集合不把 Guide 当作普通按钮。
- [W3C Gamepad](https://www.w3.org/TR/gamepad/)：standard 布局按钮及轴位置；浏览器轴为 -1…1，模拟按钮归一化为 0…1。
- [MDN Gamepad](https://developer.mozilla.org/en-US/docs/Web/API/Gamepad)：能力依赖具体平台与控制器组合，不能由单个浏览器原型证明系统级支持。

## 原型范围

五个场景均有页面内可操作状态；系统窗口、播放器、演示软件和编辑器均为示例，未连接实际应用。真手柄入口仅用于浏览器输入试用，未验证 Xbox 实机、后台全局唤出、系统快捷键冲突、原生毛玻璃或输入独占。

## 本轮验证

JavaScript 语法检查通过。Ego 浏览器中完成五个场景的关键路径：轮盘选择并确认应用；虚拟摇杆指向影音；扳机 84% 对应约 11.3×，松开归零；窗口移动与缩放、B 撤销；演示翻页、聚光与 1.83× 放大；审片逐帧、标记和入出点。980px 与 390px 视口没有页面横向溢出。此验证不代表真实 Xbox 输入或系统控制已经接通。
