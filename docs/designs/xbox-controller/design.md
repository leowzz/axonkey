# Xbox 标准手柄：SVG 映射工作区设计

入口：[交互原型](../xbox-controller.html)。所有动作只保存在 `axonkey.design.xbox-controller.v1` 预览存储，不修改应用配置、不执行映射。点击手柄图形、切换触发方式、添加和编辑动作、切换配置均可操作。

## 设计依据与范围

这是现有 Axonkey 的设备扩展：沿用设备首页 → 独立配置文件 → 映射工作区的结构，以及浅灰连续面板、细边框、蓝色选中态。严格遵守本次要求，选键只用 SVG，不提供全量按键列表或列表切换开关。

Design Read：桌面配置工具 / existing-product extension；视觉变化 2、动效 2、信息密度 7、图形依赖 6、品牌一致性 10。主要任务是在笔记本距离准确找到输入、理解触发条件并编辑动作；不改变现有产品的导航与视觉系统。

图形需要横向空间，因此此设备把原来的 228px 遥控器窄栏扩展为约 55% 宽的手柄区，右侧约 45% 是连续编辑区。默认窗口沿用 1180×820，最低桌面窗口沿用 980×680。左右独立滚动；较窄浏览器可上下排列。

## 视觉与资源约定

- 原有颜色：文字 `#2f4255`、辅助文字 `#737b84`、边框 `#dfe4ea`、蓝色 `#1478e8`、浅蓝 `#e2efff`。绿色仅表达真实输入；ABXY 保留硬件颜色用于辨识。
- 字体沿用 Manrope / Noto Sans SC，离线时回退 PingFang SC / Microsoft YaHei；没有新增远程字体依赖。
- 8px 间距基准，控件 6–8px 圆角，主工作区无层层套卡；仅动作、弹窗等有必要的区域带容器。
- SVG 鼠标与键盘聚焦均可选中，Enter / Space 等价于点击。选中用蓝色轮廓，已配置用蓝点，实际输入用绿色，并有相应文字图例。
- 按用户反馈移除中心 Xbox 标志，改用通用主页符号；设备名称、按键字母与颜色、布局和输入识别规则保持原样。
- 手柄中心与非对称摇杆位置按 Xbox 标准布局设计。用户明确要求可交互 SVG 示意图，所以使用可编辑的矢量几何，不使用产品照片代替热区。
- 现有 Axonkey 图标：`src-tauri/icons/128x128@2x.png`。设备卡片缩略图由同一个 SVG 派生，避免图形副本不一致。

## 输入模型

| 输入 | 编辑方式 | 触发行为 |
| --- | --- | --- |
| A / B / X / Y | 直接点击面板按键 | 单击、双击、长按 |
| LB / RB | 直接点击顶部肩键 | 单击、双击、长按 |
| View / Menu | 直接点击功能按键 | 单击、双击、长按 |
| D-pad 上、下、左、右 | 点击十字键各方向 | 单击、双击、长按；斜向同时激活两个方向 |
| LS / RS 按下（L3 / R3） | 点击摇杆中心 | 单击、双击、长按 |
| LT / RT | 点击顶部扳机 | 达到深度时、保持、松开；独立模拟量 |
| 左右摇杆方向 | 点击摇杆外圈方向 | 推入方向、保持、回中；方向阈值 + 回中范围 |
| 主键（Guide） | 使用通用主页符号 | 待验证后开放；不同系统保留行为单独处理 |
| Share | 仅具有该能力的设备显示 | 当前设备未验证，不默认启用 |

普通核心范围是 14 个数字输入（ABXY 4、肩键 2、功能键 2、方向键 4、摇杆按下 2）加 2 个模拟扳机、2 个双轴摇杆。摇杆方向映射是从模拟轴派生的输入，不应覆盖原始轴数据。配对键不作为应用映射输入，不包含 Elite 扩展背键。

扳机默认 40% 触发、30% 以下复位，预览可调 40%–95%；方向默认 50% 触发、15% 回中，回中范围 5%–35%。采用不同的进入/退出阈值避免边缘抖动；默认阈值是设计提议，不是硬件规格。长按/保持暂设 400ms，一次触发，不隐含持续重复。

## 状态与交互

1. 选键唯一入口为 SVG；右侧标题显示完整输入名。
2. 切换按键、触发方式、配置不丢失动作。示例配置和空白配置独立。
3. 已配置输入在图上标点；数字来自当前配置，不是硬编码统计。
4. 默认不让真实输入抢走编辑焦点。测试输入中的“按手柄选键”是显式选择；有编辑弹窗时不跳转。
5. 原型测试使用浏览器 Gamepad API，只接受已识别为 Xbox 且 `mapping === 'standard'` 的输入。没有数据时显示等待；未知布局显示待适配，不猜映射。Share 不按非标准索引猜测。
6. 原型可以根据实际收到的 Guide 事件开放该键预览。浏览器端读取成功不等于 Tauri 后台输入或拦截已完成。
7. 当前只验证了 macOS HID 读取，尚未验证独占捕获。产品默认说明“附加动作”，不能承诺原始手柄输入已被阻止。
8. 电量未验证就显示“未提供电量”；不能从连接成功推导出电量或权限全部就绪。

## 后续正式接入边界

- 新增 `src/devices/xbox-controller/`：设备定义、能力描述、SVG 输入组件、设置页和平台归一化映射；公共页根据设备声明选择图形，不为此设备提供按键列表开关。
- `deviceModel.ts` 新增设备与 `xbox.*` 输入命名空间，输入种类扩展为 gamepad；配置文件的拥有者仍为设备，保留遥控器和鼠标的数据兼容。
- `MappingPage`/`MappingFlowPage`/总览等共享入口按能力呈现，不能只在一个编辑页藏列表而在其他页重新出现全量按键列表。
- 数字按键复用已有触发/动作引擎；新增模拟输入归一化、阈值状态机、回中与设备断开复位，避免断连后按下状态残留。
- macOS 可沿用 IOHIDManager。已实测设备 `045E:02E0`、Report ID 1、16 字节报告；不把这个具体设备格式当成所有 Xbox 型号的统一格式。
- Windows 单独选择平台手柄后端并实测；浏览器 Gamepad API 只用于原型，不是桌面后台输入实现。
- 原始输入能否阻止、Xbox 键是否被系统优先处理、Share 差异、按键与连接方式兼容范围，需要真实设备验证。
- 新增持久化迁移、输入解析和阈值行为测试；验证两台同型号设备隔离、配置切换、按住时断连、多个按钮同时按下。

## 事实来源

- [Microsoft Learn：Gamepad and vibration](https://learn.microsoft.com/en-us/windows/uwp/gaming/gamepad-and-vibration)：普通 Xbox 按键、模拟摇杆、扳机和死区的定义。
- [Xbox 官方无线手柄页面](https://www.xbox.com/en-US/accessories/controllers/xbox-wireless-controller)：新款 Share 键与外观参考。
- [W3C Gamepad](https://w3c.github.io/gamepad/)：浏览器按钮/轴范围、标准布局；此处预览使用标准 0–16 号按钮，额外按键不作型号无关的假设。
- 本次对话的原生 HID 实测：报告与数值变化均成功；Xbox 键、摇杆按下是否都有物理输入验证仍须逐项确认。

## 原型验证

- 已通过 JavaScript 语法检查。
- 浏览器实测：SVG 点击与键盘 Enter 选键、模拟扳机编辑、动作新增和删除、配置隔离、刷新恢复、Share 未验证禁用、设备卡片返回。
- 1180×820 与 980×680 均无页面横向溢出和 body 双重滚动；最低窗口的长编辑内容可通过右栏滚动访问。
- 浏览器输入测试显示等待 Xbox 输入，没有把未识别状态写成已连接。此前原生 HID 实测成立，但此次没有重复操作实体手柄来验证浏览器图形反馈。
- 确认后的独立资源已保存到 `src/devices/xbox-controller/`：`xbox-controller-keymap.svg` 用于编辑示意图，`xbox-controller.svg` 用于设备卡片；该目录的 README 说明区域标识与状态样式。
- 原型确认后，已接入设备实例首页、绑定和原生 HID 监听。正式实现统一采用 55% 进入 / 35% 释放的阈值，将模拟量转换为单击、双击和长按；原型中的可调阈值与保持/松开编辑仅为设计探索。完整支持范围和验证见 [设备集成约定](../../DEVICE_INTEGRATION.md)。
