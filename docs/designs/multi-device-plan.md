# 多设备页面方案

确认日期：2026-10-24

主页负责应用运行状态与系统权限，配置文件归属于设备。采用独立的“我的设备”页面承载设备列表与接入入口，进入设备后复用现有映射编辑页面。

## 外层页面与导航

- 外层保留四个入口：**主页、我的设备、设置、关于**。
- “主页”展示软件总开关、系统权限和运行环境，保留授权、重新检测及日志入口。主页不展示型号、设备图片、电量、连接状态或设备专属音频组件。
- 主页的权限就绪只依据真实系统授权，不依赖某台设备是否连接、驱动是否安装；Windows 不根据设备驱动状态推断管理员权限。
- 主页采用紧凑单栏：页名与重新检测、应用状态摘要、系统权限、三个常用入口（我的设备、设置、运行日志）。与设备页共用浅色背景和蓝灰文字，通过间距组织内容，不使用设备宣传区或重复操作区。
- “我的设备”是单独页面，以平铺卡片展示设备。
- 点击设备卡片，进入该设备的现有映射编辑页面。
- 映射编辑页属于设备内部，不再作为外层独立入口；设备编辑页支持返回“我的设备”。
- 原来的“总览”页面暂时隐藏入口，保留页面实现。这里的“总览”指现有映射总览，不是新增加的“我的设备”页面。

## 设备编辑页面

- 设备编辑页作为右侧的完整工作区，不再保留外层独立配置工具栏。
- 工作区第一行左侧为返回按钮及紧邻的配置文件选择器，设备名称相对整个工作区居中，右侧留空。
- 左设备栏不重复放置设备名称卡片；保存状态、更多操作保留在现有按键编辑工具行。
- 设备映射编辑区保留原有层次：设备栏、主编辑区和画布各有适度的底色或边界；单击、双击、长按保留各自的浅色泳道背景。主页的简化样式不延伸到映射编辑器。
- 继续复用现有泳道、动作序列和行为库。
- 设备专属功能保留在设备内部；遥控器的音量校准位于“更多映射操作”菜单，不再占用主页。
- 每台设备独立管理自己的配置文件；同型号的不同设备也不共用配置。
- 未来的应用配置仍位于该设备的配置文件之下。

## 原型参考

早期原型：[我的设备与现有映射布局](my-devices.html)。原型中的三项导航、顶部配置与左栏返回位置已由后续确认的四项导航和工作区首行布局替代，以本说明和当前实现为准。

[第三版 HTML 原型](multi-device.html) 用于参考“设备卡片 → 设备编辑 → 返回我的设备”的页面关系。

正式编辑页以现有软件布局为准，不照搬原型新增的顶部工具栏、状态条或其他附加区域。本说明中的导航和布局约束优先于原型。

## 首期实现

开发分支：`codex/multi-device-workbench`。

- 已接入现有 RC003 遥控器和系统鼠标，设备卡片进入各自编辑页；外层四个入口、工作区首行的返回与配置选择、居中的设备名称按本方案实现。
- 新安装先进入“主页”；系统权限从主页进入，设备接入通过“我的设备”中的“集成设备”或设备状态打开。Windows 正常设置流程以设备集成、按键控制和语音输入表达，保留管理员授权、失败和重启提示。
- 配置归属设备，每类设备保留自己的活动配置。旧版共享配置自动拆成两份，保留各自映射；单配置导入导出及完整备份升级到 v2，并兼容旧版文件。
- 原生切换配置事件携带来源设备。另一设备切换配置不会覆盖当前设备映射、清空当前编辑历史或取消其原生动作队列。

现有输入后端仍以 `rc003`、`mouse` 区分输入来源；系统鼠标由所有物理鼠标共用。**同型号多台物理设备的独立身份、手柄和自定义固件协议、应用配置文件尚未实现**，后续需在输入后端与设备身份模型中继续扩展。本期界面不展示虚构的设备实例。

验证：`npm run build` 通过；`npm run test:release` 290 项通过、1 项按平台跳过；Rust 输入服务 79 项通过。浏览器已检查 1400 × 900 设备页、940 × 620 编辑页及设备导航、配置独立新增/复制。真实设备输入、Windows 实机集成与原生毛玻璃效果尚未验收。
