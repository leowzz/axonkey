# 多设备页面方案

确认日期：2026-10-24

采用已确认的 B 方案，将设备列表与系统权限合并为首页。设备卡片是主要操作入口，配置文件归属于设备，进入后继续复用现有映射编辑页面。

## 外层页面与导航

- 外层保留三个入口：**首页、设置、关于**。旧版保存的“我的设备”及已隐藏“总览”入口会迁移到首页。
- 首页左侧为并排的近方形设备卡，使用白色/浅色底与 6px 小圆角，展示真实设备状态、当前配置和配置数量；“集成设备”打开现有接入流程。
- 右侧系统权限为贯通内容区上下的连续侧栏，只有必要的左边界，不再作为悬浮卡片。设备区与权限区各自滚动，内容超出时保持可达；权限检测、管理和日志入口保留。
- 权限状态只依据真实系统授权，不依赖某台设备是否连接、驱动是否安装。浏览器明确显示预览状态，Windows 不根据设备驱动状态推断管理员权限。
- 点击设备卡片进入该设备的映射编辑页面；编辑页返回合并首页，外层仍选中“首页”。设备配置和映射数据不因导航合并而改变。
- 原来的映射“总览”仍保留实现但隐藏入口，首页不再展示大型运行状态卡。

## 设备编辑页面

- 设备编辑页作为右侧的完整工作区，不再保留外层独立配置工具栏。
- 工作区第一行左侧为返回按钮及紧邻的配置文件选择器，设备名称相对整个工作区居中，右侧留空。
- 左设备栏不重复放置设备名称卡片；保存状态、更多操作保留在现有按键编辑工具行。
- 设备映射编辑区保留原有层次：设备栏、主编辑区和画布各有适度的底色或边界；单击、双击、长按保留各自的浅色泳道背景。主页的简化样式不延伸到映射编辑器。
- 继续复用现有泳道、动作序列和行为库。
- 设备专属功能保留在设备内部；遥控器的音量校准位于“更多映射操作”菜单，不再占用主页。
- 每台设备独立管理自己的配置文件；同型号的不同设备也不共用配置。
- 未来的应用配置仍位于该设备的配置文件之下。

## 原型参考

已确认 [B 方案：设备与权限分栏](device-home-options.html?option=b)，设备卡调整为并排近方形。实现时进一步将右侧权限栏改为贯通上下的连续区域；原型保留用于回看比较，布局细节以当前实现为准。

早期原型：[我的设备与现有映射布局](my-devices.html)。原型中的页面关系和返回位置仅供历史参考，导航合并与工作区首行布局以本说明和当前实现为准。

[第三版 HTML 原型](multi-device.html) 用于参考“设备卡片 → 设备编辑 → 返回我的设备”的页面关系。

正式编辑页以现有软件布局为准，不照搬原型新增的顶部工具栏、状态条或其他附加区域。本说明中的导航和布局约束优先于原型。

## 首期实现

开发分支：`codex/multi-device-workbench`。

- 已接入现有 RC003 遥控器和系统鼠标，设备卡片进入各自编辑页；外层导航已合并为三个入口；工作区首行的返回与配置选择、居中的设备名称继续保留。
- 新安装先进入合并首页；系统权限从右侧栏进入，设备接入通过首页“集成设备”或设备状态打开。Windows 正常设置流程以设备集成、按键控制和语音输入表达，保留管理员授权、失败和重启提示。
- 配置归属设备，每类设备保留自己的活动配置。单配置导入导出及完整备份使用 v2；旧版共享配置转换和旧文件兼容已移除。
- 原生切换配置事件携带来源设备。另一设备切换配置不会覆盖当前设备映射、清空当前编辑历史或取消其原生动作队列。

现有输入后端仍以 `rc003`、`mouse` 区分输入来源；系统鼠标由所有物理鼠标共用。**同型号多台物理设备的独立身份、手柄和自定义固件协议、应用配置文件尚未实现**，后续需在输入后端与设备身份模型中继续扩展。本期界面不展示虚构的设备实例。

本轮合并验证：`npm run build` 通过；`npm run test:release` 301 项通过、1 项按平台跳过。浏览器已检查 980 × 680 首页、设备进入与返回、配置独立复制、权限设置和集成弹窗，以及暂停状态；长列表布局样例经真实滚轮滚动，右侧权限栏和侧导航保持固定，末项可达。此前 Rust 输入服务 79 项测试通过，本轮未改动原生输入逻辑。真实设备输入、Windows 实机集成与原生毛玻璃效果尚未验收。
