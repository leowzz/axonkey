# 0004 快捷交互窗复用独立配置文件与非激活顶层浮层

- 状态：`accepted`
- 关联 Issue：[#87](https://github.com/leowzz/axonkey/issues/87)

## 背景

用户在物理遥控器、小键盘、手柄或鼠标上配置大量 Prompt（粘贴文本、模拟输入、复合序列）与快捷动作时，物理按键数量多且无自定义丝印标识，难以凭记忆准确触发。

用户需要通过按下指定触发键进入「快捷交互窗」模式：在屏幕顶层清晰预览该模式下其他按键的功能，按下任意已配按键立即退出模式并执行对应功能，或再次按下触发键直接退出模式。该模式唤起的是一整套独立的按键配置，而非当前常驻配置的临时预览。

## 决定

1. **配置模型复用设备 `Profile` 并以 `quick` 标记区分角色**：
   - 新增行为类型 `quickOverlay`（字段 `profileId`），指向同一设备下的目标配置文件。
   - 设备配置文件（`InstanceProfile` 与 `MappingProfile`）新增可选布尔字段 `quick`（默认 `false`，序列化省略 `false` 以保持旧文件与云端结构兼容）。
   - 快捷配置完整复用现有映射存储、工作流编辑器、撤销/重做、备份与云同步链路；同时在编辑器中独立编辑快捷配置时不改动设备当前常驻 `activeProfileId`，`switchProfile`（上/下一配置循环与全局按键同步）仅作用于常驻配置（`!quick`），避免误切入单次唤起面板或覆盖面板内部按键。
2. **输入线程内建单次模态状态机**：
   - `NativeSettings` 同步携带设备的 `quickProfiles` 快照，使各平台输入后端（通用 HID、macOS RC003 / A15、Windows Quarbor 通道、系统鼠标）在本地零往返延迟下完成模态切换：
     - 触发键进入模式后忽略当次按下对应的物理抬起边沿；
     - 再次按下原触发键立即退出模式并吞掉配对抬起边沿，不触发任何动作；
     - 按下其他已配置按键按快捷配置手势解析，产出执行序列后立即退出模式并执行；未配置按键仅退出模式，不回退发送设备原始键值。
3. **非激活（Non-activating）全局顶层 WebView 浮层**：
   - 使用预热常驻的透明顶层窗口（`index.html?view=quick-overlay`），在 macOS 通过 `NSStatusWindowLevel` + 全屏辅助空间集合行为并 `orderFrontRegardless` 展示，在 Windows 通过 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_TOPMOST` 与 `SW_SHOWNOACTIVATE` 展示。
   - 浮层全程不抢占前台应用焦点，确保退出模式后紧随执行的粘贴文本、模拟输入文字与组合键直接送达用户原本聚焦的输入框。

## 主要取舍及影响

- **取舍：独立 `Profile` 引用 vs 在行为内嵌套子映射表**
  - 若在 `quickOverlay` 行为内部嵌套完整 `BehaviorMap`，会导致工作流、历史栈、设备热区校验与云同步出现第二套平行数据结构。复用设备 `Profile` 配合 `quick` 标记，用极小的数据扩展获得完整的编辑能力、设备 SVG 视图和跨端同步兼容。
- **取舍：未配按键退出不透传原始键**
  - 常驻配置下未配单击会保留遥控器原始键值（如返回键发送 Delete、语音键发送 F5）；但在快捷交互模式下，用户盯着屏幕面板选键或按返回取消时，若未配按键透传 Delete/Enter 会破坏当前编辑器输入内容，因此快捷模式下未配置按键仅安全退出模式。
