# 传输无关的设备输入与会话

状态 `proposed`（仅设计，尚未实施）

对应 [Issue #58](https://github.com/leowzz/axonkey/issues/58)，详见[设备输入源设计](../DEVICE_INPUT_SOURCES.md)。

## 背景

[ADR 0002](0002-svg-device-descriptor.md) 已让六种现有设备共用 SVG 描述与报告引擎，但运行入口仍主要接收 HID/GATT 报告。手机和其他网络设备还可能提供语义按键、连续触摸及音频，不能要求它们伪装成 HID，也不能把全部数据压成按键值或动作序列。

当前 `DescriptorEngine` 同时负责字节解码与输入状态更新；语音能力又要求触发键和设备编解码后端。直接沿用这些入口会混淆传输、输入类型和平台输出能力。

## 决定

- 设备会话共用实例绑定、配置、连接状态与结束清理。运行时仍以 `(instanceId, stableKey)` 寻址；网络地址不作为持久化实例身份。
- 报告适配器先解码 HID/GATT 数据，网络语义适配器接收已声明的输入；两者汇入统一控制状态入口，复用现有状态组、阈值、映射和实例隔离。
- 控制值、结构化多触点和音频分别处理。按钮边沿进入现有手势层；触摸保留接触点身份、坐标与开始、移动、结束、取消；音频走独立流与音频服务，不进入动作队列或前端状态事件。
- 断连、禁用或切换会话时清空控制状态、取消触摸手势、终止音频流并释放该会话持有的输出。取消不合成点击或正常手势完成。
- 输入 source 与字节 report 解耦。语义输入显式声明其来源，不伪造 HID usage 或厂商 engine。实现使用必要的枚举和适配函数，不建立插件总线。
- SVG 继续描述设备类型、图形、热区、稳定输入和能力；配对凭据、地址、会话状态及媒体数据留在运行时。

### 描述协议与兼容

新草案使用 `axonkey.device/2` 与 `urn:axonkey:device:2`。输入 source 的 union 和独立音频能力扩大了解析契约，采用新主版本使旧应用明确拒绝启用，而非静默忽略必需能力。

v1 与 v2 解析到相同内部模型。六份现有 v1 SVG、稳定 ID、`legacy-key` 和已有配置保持兼容，不要求立即重写设备文件或报告引擎。旧语音描述适配到内部音频能力，新的音频输入允许没有触发键。

### 网络首版

采用局域网 WSS，每个设备会话使用一条连接：JSON 承载控制与触摸，二进制帧承载音频。入口只校验一次外部数据，随后传递明确类型。队列有界，控制与生命周期事件、连续采样、音频分别制定溢出处理，不能让音频挤占按键释放或触摸取消。

此选择复用可靠有序传输，减少首版实现成本；它不承诺 TCP 下无抖动或无队头阻塞。先测量真实设备的延迟与音频连续性，出现实际问题后再选择其他媒体传输，不预建多传输框架。

## 取舍和影响

优点是新增来源可以复用现有设备配置、SVG 与控制引擎，连续触摸和音频也有明确的生命周期。代价是需要扩展描述解析、会话入口及类型路由，且新增来源必须声明其输入能力。

能接收连续信号不等于能完成全部输出。触摸板移动、滚动、拖动或原生多点触控需要相应的连续映射与平台输出能力；虚拟麦克风也依赖现有平台音频输出及必要驱动。网络输入本身不要求 HID 驱动。

实施先提取共享状态入口并验证已有设备，再加入语义来源、触摸及音频；按实际重复整理会话代码。云端 SVG 分发、发现下载和其他媒体传输留待后续。

## 验收边界

本记录仅确认设计方向，不代表网络接入或连续输出已经实现。实施时分别验证旧设备兼容、同型号多实例隔离、断连取消、触摸连续性、音频连续性与平台输出；详细步骤和结果记录在 Issue #58。
